# Тесты API

Чёрный ящик: тесты ходят по HTTP в уже запущенный сервер `platform-core`
и проверяют реальные ответы, без моков. Часть тестов (управление ролями от
имени admin) дополнительно подключается напрямую к Postgres — назначить
первую admin-роль в тестах иначе нельзя, потому что API для этого само
требует уже существующего admin (см. `docs/rbac.md`).

## Как запустить

```bash
# из ev-core/
make docker-up
make migrate-up
export $(grep -v '^#' .env | xargs)
make run &   # поднять API в фоне

go test ./tests/...
```

## Переменные окружения

- `BASE_URL` — адрес API, по умолчанию `http://localhost:8080`.
- `TEST_DATABASE_URL` (или `DATABASE_URL`) — строка подключения к Postgres
  для фикстуры admin-роли, по умолчанию как в `.env.example`.

## Поведение без поднятой инфраструктуры

Если API недоступен — тесты сами помечаются `SKIP` (см. `requireServer`
в `client.go`), а не падают. Если недоступна БД — `SKIP` получают только
тесты, которым нужен прямой SQL-доступ (`makeAdmin` в `db.go`), остальные
проходят как обычно.

## Что покрыто

- `health_test.go` — `GET /health`.
- `auth_test.go` — регистрация (успех/дубликат email/невалидный email/слабый
  пароль), логин (неверный пароль/несуществующий email — оба должны давать
  одинаковый `401 invalid_credentials`, защита от user enumeration), ротация
  refresh-токена и отказ при повторном использовании, logout.
- `rbac_test.go` — доступ без токена и с невалидным токеном (`401`), default
  deny для свежего пользователя с ролью `member` без прав (`403 access_denied`).
- `coreapi_admin_test.go` — CRUD от имени admin: список пользователей без
  `password_hash` в ответе, получение пользователя (включая `404` для
  несуществующего), список ролей, назначение/повторное назначение
  (идемпотентность)/отзыв роли, отказ при несуществующем `role_id`.
